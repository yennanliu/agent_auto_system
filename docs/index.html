The harness layer

A control plane between the executor and CrewAI

It owns LLM selection, validation, evaluation, retries, and cost tracking — so business logic never touches any of it. Six responsibilities, one clean seam.

Multi-LLM, per run

Pick OpenAI, Anthropic Claude, or Google Gemini from the UI. normalize() resolves the model without an API call; resolve() builds the crew's LLM at a job-specific temperature.

Self-correcting retries

A validator checks every result. On failure the executor re-runs the flow with previous_error injected, so the LLM fixes its own mistake on the next attempt.

Cross-model fallback

Transient outages (503, 429, timeouts) advance through sibling models with exponential backoff — up to 5 attempts. Hard errors raise immediately.

LLM-as-judge scoring

An independent model scores every result 0–100 with confidence — never the model that produced it. Per-job rubrics ground the score; a heuristic fallback keeps it honest.

Token & cost tracking

Every run records provider, model, tokens in/out, retry count, eval score, and estimated USD. /api/stats aggregates it all in a single SQL pass.

Observability

Live SSE progress every 0.5 s, a rich /health, and optional per-run Langfuse traces — all degrade gracefully and never break a run.

How a run works

Trigger, execute, validate, score

FastAPI returns 202 immediately and runs the flow in the background. The UI opens an SSE stream and watches it move.

1

Create & trigger

POST /api/jobs stores the payload; /run spawns an asyncio task and returns 202.

2

Resolve the LLM

Executor normalizes the provider/model and dispatches the job type to its Flow.

3

Run the crew

Flow → Crew → Tools produce structured JSON. Transient outages fall back across models.

4

Validate

A per-job rule checks the result. Fail with retries left → re-run with the error injected.

5

Judge

An independent LLM scores quality 0–100. Purely informational — it never flips success.

6

Record & stream

Tokens, cost, retries, and eval land in one write; the terminal status streams to the UI.

Guide

From zero to your first scored run

Clone it, add one LLM key, and trigger a real automation in a few minutes. The walkthrough below uses live screenshots of the running app.

1

Set up & launch

1

Clone and install

Dependencies are managed with uv. The Playwright step is only needed for browser-driven jobs (form fill, Shopee, X, Tasker, email collector).

$ git clone https://github.com/yennanliu/agent_auto_system
$ cd agent_auto_system
$ uv sync                                # install deps
$ uv run playwright install chromium     # for browser jobs
2

Add at least one LLM key

Copy the sample env and fill in an OPENAI_API_KEY, ANTHROPIC_API_KEY, or GEMINI_API_KEY — any one is enough to start. Keys can also be stored (encrypted) later from the Admin page.

$ cp .env.example .env
$ # edit .env → set OPENAI_API_KEY=sk-… (or ANTHROPIC / GEMINI)
3

Start the server

Run the FastAPI app and open it in your browser. Tests are a good first sanity check.

$ uv run uvicorn src.main:app --reload --port 8000
$ open http://localhost:8000
4

Sign in

The app is login-gated. On first startup an admin is seeded — sign in with admin / admin.

⚠️Change this before exposing the app. The seed only runs while the users table is empty; afterwards manage users and passwords from the Admin page.
2

Run your first automation

We'll run the Hacker News Digest — no external accounts required, just an LLM key. It reads the top HN stories and returns a themed, structured summary.

1

Open “+ New Run” and pick an automation

The picker lists all built-in job types. Choose HN Digest. Each tile swaps in its own form below.

2

Fill the form and choose a model

Set Number of Stories to 5, then pick a provider and model. This demo uses OpenAI · gpt-4o-mini — fast and cheap. Every LLM-backed job carries its own temperature under the hood.

3

Watch it run — live

Hit Run ▶ and you land on Activity. A server-sent-events stream updates the step graph (Start → Validate → Fetch → Digest → Verify → Evaluate → Done) and appends log lines every half-second.

4

Read the scored result

When the run finishes, expand it to see the structured JSON under Result, plus Flow, Log, and Usage tabs and a Copy JSON button. An independent judge scored this run ★100.

✅This exact run: hacker_news_digest on gpt-4o-mini — finished in 19.5 s, validated, and scored 100/100 by an independent judge model.
3

Explore the key features

Once a few runs are in, the rest of the app comes alive. Here's what to look at next.

Run history & self-correcting retries

Every run carries a status, provider badge, and eval score. Failed runs (e.g. “Server restarted while running”) expose a one-click Retry — and the validator re-injects the previous error so the LLM can fix itself.

Analytics — cost & quality

The Analytics tab breaks down runs by automation and by provider/model: success rate, average eval score, tokens, estimated USD, and average duration — all aggregated server-side.

System Catalog

Inspect every agent, tool, and crew — roles, goals, backstories, and the actual source config — straight from the System tab. Great for understanding how each automation is wired.

Admin — users, keys & toggles

Create users and scope which automations each may run, store Fernet-encrypted API keys, pick the eval-judge model, and globally enable/disable job types.

🐳Prefer containers? One command: docker compose up --build -d then open http://localhost:7000. See the repo's Docker quick start and AWS ECS Fargate guide.
